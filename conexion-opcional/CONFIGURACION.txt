CONEXIÓN POR SALA — CLOUDFLARE WORKERS + D1
=========================================
Este componente es opcional. Automatiza el intercambio de códigos WebRTC.
No recibe archivos ni ofrece almacenamiento de fotos/documentos.

Usa una cuenta con Workers FREE. No selecciones un plan de pago ni introduzcas
una tarjeta. Si tu cuenta pide contratar algo, no continúes con esa contratación:
la app puede usarse con el método manual. Las cuotas gratuitas pueden limitar
nuevas conexiones; no se promete un servicio ilimitado.

OPCIÓN CON EL PANEL WEB (SIN INSTALAR HERRAMIENTAS)
1. En Cloudflare abre Workers & Pages > Create application.
   Crea un Worker de ejemplo Hello World llamado intercambio-conexion.
2. En D1 SQL database crea una base llamada intercambio-conexion.
   Abre su consola SQL y ejecuta las cuatro sentencias de schema.sql.
   Puedes ejecutarlas de una en una. Crean tablas e índices, no borran tus datos.
3. En el Worker, pestaña Bindings > Add binding > D1 database.
   Variable name: DB (exactamente así). Selecciona la base que acabas de crear.
4. En Settings > Variables and Secrets añade la variable de texto ALLOWED_ORIGIN.
   Valor: el origen HTTPS de TU página de GitHub, sin ruta y sin barra final.
   Ejemplo: https://domingo.github.io
   No pongas https://domingo.github.io/intercambio-wifi/ en esta variable.
5. En el editor del Worker, sustituye el ejemplo por TODO el contenido de worker.js.
   Guarda y despliega. Copia la dirección HTTPS del Worker.
6. Para la limpieza periódica, añade un Cron Trigger: */20 * * * *
   El código también limpia registros caducados al crear nuevas salas.
7. En config.js, cambia signalUrl por la dirección del Worker. Por ejemplo:
   window.INTERCAMBIO_CONFIG = { signalUrl: 'https://intercambio-conexion.TU_SUBDOMINIO.workers.dev' };
   Sube config.js a GitHub y espera a que se publique la actualización.
8. Abre la página de GitHub en los DOS dispositivos. Si antes guardaste una dirección
   manual en Ajustes, actualízala allí también; tiene prioridad sobre config.js.

El origen y la URL del Worker no son contraseñas. No pongas tokens de Cloudflare,
contraseñas ni claves de tu cuenta dentro de config.js ni en el repositorio.

ALTERNATIVA CON LÍNEA DE COMANDOS (PARA QUIEN YA USE WRANGLER)
Desde esta carpeta, con Node y Wrangler preparados:
1. Copia wrangler.example.toml como wrangler.toml.
2. Ejecuta npx wrangler login
3. Ejecuta npx wrangler d1 create intercambio-conexion
4. Copia el database_id real devuelto a wrangler.toml y ajusta ALLOWED_ORIGIN.
5. Ejecuta npx wrangler d1 execute intercambio-conexion --remote --file=schema.sql
6. Ejecuta npx wrangler deploy
7. Copia la URL devuelta a config.js y publica ese archivo en GitHub.
No ejecutes nada de contratación o cambio de plan.

COMPROBACIÓN
Desde la página de GitHub pulsa Crear invitación. Debe aparecer un código de sala
con 16 caracteres. En el otro dispositivo introduce ese código o escanea el QR.
Si falla el servicio, la creación ofrece un código manual como alternativa.
No pruebes el Worker abriendo su URL directamente: el servicio exige solicitudes
originadas desde tu página y puede responder Origen no permitido al abrirlo solo.

PRIVACIDAD Y LÍMITES IMPLEMENTADOS
- Datos técnicos de invitación/respuesta: acceso mediante un código aleatorio de sala.
- Código de sala de 80 bits. Secreto adicional de 256 bits para el creador.
- Solo se admite una respuesta por sala; compara siempre el código de verificación.
- Caducidad de 10 minutos; borrado por el creador al conectar y limpieza de caducados.
- Peticiones de señalización limitadas a 22 KB. No hay endpoints de archivos.
- Límite de 120 solicitudes/minuto/IP y 10 salas/minuto/IP.
- No se guarda la IP en claro en la tabla de límites.
- CORS restringido al origen configurado. CORS por sí solo no es autenticación.
- Las copias operativas de Cloudflare se rigen por las políticas del proveedor.
